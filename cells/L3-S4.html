3층 도구 × ④ 과제 설계자

AI에게 나를 어떻게 알려주고 일을 어떻게 시키나

칸 안의 순서 실전 6단계 — 3분할 → 병목 5신호 → 흐름 7칸 → 과제 문장 → 가장 작게 → 측정·검증

  1. 과제 문장과 숫자 하나 — baseline 심기만들 예정 — 「무엇을 얼마나 줄이나」 과제 문장 하나를 쓰고 지금 값(baseline)을 숫자 하나로 재어 둔다 — 「됐다」는 기준선이 있을 때만 말할 수 있다 (실전 4단계).
  2. 하네스 — AI가 일하는 틀과 지침 파일만들 예정 — 하네스·지침 파일(MD)·스킬·커넥트·에이전트 다섯 구역의 지도를 한 장으로 익히고, 지침은 대화가 아니라 파일에 둔다는 원칙을 세운다.
  3. 받은 스킬 설치 → 수정 → 내 스킬만들 예정 — 공유판 스킬 하나를 설치해 돌려 보고, 공개 스킬을 내 환경에 맞게 「머리말로 덮는」 식으로 고쳐 내 것으로 만든다.
  4. 커넥트와 API — 손이 닿는 범위만들 예정 — 커넥터(포트에 꽂기)와 API(창구 부르기)의 차이, 커넥터가 못 하는 일, 연결 상태 경고를 읽는 법을 익히고 — 조회가 성공했다고 답이 맞는 것은 아님을 흔한 질문으로 대조해 확인한다.
  5. AI에게 브라우저를 맡기는 네 길과 금지선만들 예정 — 내장 브라우저·크롬 확장·동행 브라우저·repl 브라우저 네 길을 비교하고, 캡차·비밀번호·되돌릴 수 없는 클릭은 사람이 한다는 금지선과 「분류기가 막는 일은 우회 말고 API로」 원칙을 세운다.
  6. 로그인은 사람이, 그 뒤는 AI가만들 예정 — 로그인·결제·게시 같은 문턱은 사람이 넘기고 그 뒤의 조회·내려받기·편집을 AI가 이어받는 동행 모델을 익히며, 「완료」는 화면을 다시 읽어 확인하고 자동 일괄 수집은 하지 않는다.
