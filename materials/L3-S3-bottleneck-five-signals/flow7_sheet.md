## 3. 다섯 신호

겪는 것에 모두 ✓, 그중 가장 자주 겪는 하나에 ★.

| 신호 | 이렇게 보인다 | ✓ | ★ |
|---|---|---|---|
| 대기 | 남의 회신 · 승인을 기다리며 멈춰 있다 | | |
| 재작업 | 같은 것을 두 번 이상 다시 만든다 | | |
| 담당자 의존 | 특정한 한 사람(나 포함)이 없으면 안 돌아간다 | | |
| 시스템 단절 | 이 프로그램에서 저 프로그램으로 손으로 옮겨 담는다 | | |
| 예외 폭증 | 규칙대로 되는 게 없고 매번 예외 처리를 한다 | | |

## 4. 흐름 7칸

상태는 넷 중 하나: 매끄럽다 / 조금 걸린다 / 여기서 막힌다 / 아예 안 한다. 안 하는 칸도 비워 두지 않습니다.

| 칸 | 하는 일 | 2의 기록에서 해당하는 부분 | 상태 | 보이는 신호 |
|---|---|---|---|---|
| 요청 | 일이 들어오는 입구 | | | |
| 판단 | 무엇을 어떻게 할지 정하기 | | | |
| 처리 | 실제로 만들기 | | | |
| 검수 | 확인하고 고치기 | | | |
| 전달 | 넘기고 나누기 | | | |
| **기록** | 남기기 | | | |
| **재사용** | 지난번 것을 다시 꺼내 쓰기 | | | |

### (선택) AI에게 칸 나누기를 맡길 때의 지시문

붙이기 전에 실명 · 환자 정보 · 식별자를 내 손으로 지웁니다. 넣어도 되는지 모르겠으면 넣지 않습니다. 지시문 아래에 2의 기록을 그대로 붙입니다.

```text
아래는 내가 최근에 실제로 한 일 하나를, 있었던 순서대로 적은 것이다.
1) 이 일을 일곱 칸(요청·판단·처리·검수·전달·기록·재사용)으로 나눠 표로 만들어라.
   각 칸에는 내가 적은 문장만 옮기고, 내가 적지 않은 칸은 [빈칸]으로 둬라.
2) 칸마다 상태 후보 하나를 달아라: 매끄럽다 / 조금 걸린다 / 여기서 막힌다 / 아예 안 한다.
   그 판단의 근거가 된 내 문장을 옆에 적어라.
3) 다섯 신호(대기·재작업·담당자 의존·시스템 단절·예외 폭증) 중 보이는 것을 칸마다 표시하라.
최종 판정은 내가 한다. 내가 적지 않은 사실을 지어내지 마라.
```

## 5. 병목 메모 — 한 줄

```text
막힌 칸: ______ · 신호: ______ · 못 넘기는 이유: ______ · 처방 방향: ______
숫자 하나(어림): ______
```

처방 방향 고르기:

| 막힌 곳 · 못 넘기는 이유 | 처방 방향 |
|---|---|
| 기록 · 재사용 | 남기는 구조 (기억 3계층) |
| 검수 · 품질이 걱정된다 | 검증하는 고리 |
| 처리 | 가장 작게 하나 만들기 |
| 설명이 더 오래 걸린다 · 방법이 내 머릿속에만 있다 | 머릿속 방법을 글로 꺼내기 |
| 맡길 사람이 없다 | AI가 그 자리에 바로 |

숫자 하나: 남을 기다린 시간, 또는 1회 ___분 × 월 ___회 = 월 ___분 (예: 1회 20분 × 월 8회 = 월 160분 — 지은 값). 정확히 재는 일은 다음 칸에서 합니다.

## 6. 「됐다」 점검

- [ ] 업무 전환 — 막힌 칸 하나에 이름을 붙였고, 어림 숫자 하나를 적었다.
- [ ] 지식 전환 — 7칸 그림이 파일이나 사진으로 남았다.
- [ ] 역할 전환 — AI를 끼울 칸을 내가 정했다.
